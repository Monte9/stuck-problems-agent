# M4 — Legal-Admissibility and Fourth-Amendment Constraints on the Triage Schema

**Problem:** CSAM Report Triage — turning 21M CyberTipline reports into a ranked rescue docket
**Milestone:** M4 — Legal-admissibility constraints bounding how the M3 triage schema may be built and used
**Date:** 2026-06-24
**Builds on:** M3 feature schema (`artifacts/2026-06-24-m3-triage-feature-schema.md`, 8 features F1–F8), M1 rubric, M2 noise-tax scorecard.

The M3 schema ranks reports by combining intake-readable signals (imminent-danger narrative, sender identity, victim-age flags) with *enrichment* steps (hash-matching against the NCMEC/PhotoDNA corpus, IP geolocation, re-scoring with the M1 rubric) — and several features depend on a human or machine actually *viewing* or *opening* the reported files. That viewing is the legal fault line. Because NCMEC is a federally-chartered entity that is statutorily obligated to forward every report to law enforcement, a court can treat NCMEC's (and any downstream officer's) opening of a file as a **government search**. Under the private-search doctrine (*United States v. Jacobsen*, 466 U.S. 109 (1984)), that government search is only warrant-free to the extent it does **not exceed** the private platform's antecedent search. The circuits split sharply on whether opening a *hash-flagged-but-never-human-viewed* file exceeds that private search. The consequence for this project: **intake-only flags carry little admissibility risk, but the enrichment and viewing-dependent features (F3, F4, F6, and any F1/F2/F7 value derived from opening files) carry suppression risk that varies by circuit.** A triage tool that quietly assumes it may open and re-examine everything could manufacture the very Fourth-Amendment violation that gets the evidence thrown out. This artifact documents the binding constraints, maps each to the M3 features it touches, and flags where the schema must stay jurisdiction-agnostic.

## 2. Per-feature admissibility note (F1–F8)

Cross-referenced to the constraints in §1. The recurring distinction: **intake-readable text fields** carry little Fourth-Amendment risk because reading a narrative the platform wrote and transmitted is within the private-search baseline (C5); **enrichment that opens/re-examines files** carries the C1–C4 viewing risk.

- **F1 — Imminent-danger flag (intake; narrative + urgency field).** **Constraints touched: C5; C1/C2/C3 only if the imminence determination requires opening files the platform never viewed.** Reading the platform's narrative and urgency field is reading what the provider chose to include (§ 2258A(b), C5) — within the private-search baseline, low risk. *But* if an analyst escalates "imminent danger" only after *opening* attached media the platform hash-flagged-but-never-viewed, the value becomes viewing-dependent and inherits the C2/C3 search problem. Design rule: F1 should be computed from the *textual* urgency/narrative fields, not from independently opening media. **`[inference]`** — that the textual-field branch is low-risk follows from Jacobsen/§2258A(b), but no case squarely blesses an automated triage tool *reading* the narrative; the inference is that reading transmitted text the provider supplied does not exceed the provider's search.

- **F2 — Sextortion/enticement/first-person-contact indicator (intake; narrative + chat field).** **Constraints touched: C5; C1 if derived from opening communications the platform did not itself review.** Same structure as F1: a chat/communication field the platform *included* per § 2258A(b) is within scope. Risk arises only if the contact signal is extracted by an analyst reading communications beyond what the platform reviewed (Jacobsen scope, C1). Generally intake-safe.

- **F3 — Novel-vs-known-hash status (ENRICHMENT; hash match against NCMEC/PhotoDNA corpus).** **Constraints touched: C1, C2, C3, C4 (the core circuit-split feature), C5, C6.** This is the highest-risk feature. (a) Computing a *hash and comparing it* is itself analyzed as minimal/no search where the platform already hashed (Reddick/Miller reasoning, C4) — but Ackerman (C2) treated NCMEC's *opening* of non-matching attachments as a search. (b) The **novel** branch (no match) is exactly the Ackerman fact pattern: opening a never-classified file to confirm it is CSAM is a government search that exceeds the platform's automated flag — warrant-risk in every circuit, squarely barred analysis in the 9th (C3/Wilson). (c) The **known-hash** branch is *permitted* in the 5th/6th (C4/Reddick/Miller) but *not* in the 9th if no human ever viewed that specific file (C3/Wilson). Design rule: F3 may be computed from the *hash comparison metadata* (match / no-match / partial) without opening the file; **the schema must NOT require opening the file to set F3.** A "novel" file should be queued for a *warrant* before viewing, not viewed to confirm novelty. F3 also implicates the preservation clock (C6) since deferred novel files must be retained.

- **F4 — U.S.-actionable jurisdiction (ENRICHMENT; geolocate upload/login IP, address).** **Constraints touched: C5, C7; minimal C1.** Geolocating an IP/address that the provider *included* in the report (§ 2258A(b), C5) is processing transmitted metadata, not opening private content — low Fourth-Amendment search risk. The real constraint is **C7 (§ 2258A(g)) disclosure limits**: routing a prioritized report across ICAC task forces or to a foreign agency, and any cross-agency sharing of the queue, must stay within the enumerated permitted recipients. IP geolocation itself is generally not a "search" of content. **`[inference]`** — treating IP geolocation as outside Fourth-Amendment search risk is an inference from the metadata-vs-content distinction; *Carpenter v. United States* (601 U.S. — historical CSLI) shows location data can be sensitive, but a single upload IP in a CSAM report is closer to transmitted metadata than to long-term tracking. Flagged as an inference, not a holding.

- **F5 — Sender reliability (intake; submitting-ESP field lookup, consumes M2 tier).** **Constraints touched: no Fourth-Amendment / private-search constraint identified; C7 and C8 (operational).** Reading the submitting-ESP field and mapping it to an M2 tier touches no content and no viewing — no search-doctrine constraint. The relevant limits are operational: any *feedback* of sender-quality findings to platforms must use metadata, not visual depictions (C7 / § 2258A(g)'s bar on returning depictions), and a sender-based *down-ranking* rule must not be operated so recklessly that it buries real victims (C8 / § 2258B liability-shield exception). No admissibility/suppression constraint on the feature value itself.

- **F6 — Report completeness, banded M1 score (ENRICHMENT; run M1 rubric over fields).** **Constraints touched: C1, C2, C5, C6.** Scoring *field presence* (is there an IP? a file? an account ID?) from what the provider included is low-risk (C5). But if the M1 rubric is scored by an analyst *opening attached media* to assess quality, that re-opening inherits the C1/C2 viewing problem — re-examining content beyond the platform's view exceeds the private search. Design rule: F6 should be scored from **field-presence metadata**, not from opening files to judge their content. The preservation clock (C6) also bears on F6 because a deferred low-completeness report may lose its context files.

- **F7 — Victim-age / self-generated-by-young-minor indicator (intake; narrative + victim field).** **Constraints touched: C5; C1/C2/C3 if age is determined by opening media the platform never viewed.** A victim-age value taken from the provider's victim-information field or narrative is within the private-search baseline (C5). But age is frequently *only* assessable by viewing the image — and if that viewing is of a hash-flagged-but-unviewed file, the value becomes viewing-dependent and inherits Ackerman/Wilson risk (C2/C3). Design rule: prefer the textual victim field; treat any age signal that *requires* opening a never-viewed file as enrichment subject to the F3 warrant discipline.

- **F8 — Duplicate-burst / viral-meme penalty (intake self-flags / ENRICHMENT burst-count).** **Constraints touched: C1/C4 for hash-based burst-counting; C8 (operational).** The *self-flag* branch ("Potential Meme" / "Generative AI" flags the platform set) is intake metadata — no search-doctrine constraint. The *burst-count* enrichment compares hashes across the recent queue: this is hash-comparison metadata (Reddick/Miller-style, C4) and does not require *opening* files, so it is low-risk on the search axis. The operational constraint is C8: an over-aggressive viral/no-victim penalty that buries a genuine novel case could implicate the § 2258B reckless-disregard exception. No suppression constraint on the value itself, provided burst-counting stays at the hash level.

**Summary of mapping:** intake-only, content-free features (**F5, F8 self-flag branch**) → *no Fourth-Amendment/private-search constraint identified* (only operational C7/C8). Text-field features (**F1, F2, F7, F4**) → low search risk via C5, escalating only if values are derived by opening never-viewed media. Enrichment/viewing features (**F3, F6, and the open-the-file branches of F1/F2/F7**) → the C1–C4 search and suppression risk, with **F3 the single feature that sits directly on the Ackerman/Wilson ↔ Reddick/Miller circuit split.** Every one of F1–F8 is mapped above.

## 3. Limitations / uncertainty (circuit splits, unsettled questions, agnostic design)

**1. The central circuit split on opening hash-flagged files (C3 vs. C4) — unresolved and directly governs F3.** The 9th Circuit (*Wilson*, 13 F.4th 961) holds that opening a file matched only by hash — where no human at the platform ever viewed *that specific file* — **exceeds** the private search and needs a warrant. The 5th and 6th Circuits (*Reddick*, 900 F.3d 636; *Miller*, 982 F.3d 412) hold the **opposite**: a hash match gives "virtual certainty" so opening reveals nothing new. The Supreme Court has not resolved this (the *Miller* cert petition was filed but the split persists; a 2025 Fourth Circuit case, *No. 24-4546*, shows the tension is still live as of late 2025, https://www.ca4.uscourts.gov/opinions/244546.P.pdf). **Design consequence:** the schema must stay *agnostic* — F3 must be computable from hash-match *metadata* without requiring any file to be opened, so the tool never depends on a viewing step that is lawful in Houston but suppressible in San Francisco. The schema flags "novel" for warrant-first handling rather than view-to-confirm.

**2. Whether NCMEC is a "government entity" or "government agent" is not nationally settled.** *Ackerman* (10th Cir.) squarely held NCMEC is a governmental entity whose searches are Fourth-Amendment-constrained, reasoning from NCMEC's statutory duty to forward every report. But this is a *circuit* holding, not a Supreme Court ruling, and other courts have analyzed NCMEC's status more narrowly or as a fact-specific agency question. The degree to which NCMEC's *automated* hash-matching (versus a human analyst's opening) counts as government action is also unsettled. **Design consequence:** the schema cannot assume NCMEC-side enrichment is "private" and risk-free; it treats NCMEC analyst viewing as potentially government action everywhere, which is the conservative (suppression-avoiding) posture.

**3. The Fourth-Amendment status of IP geolocation metadata (F4) is an inference, not a holding here.** Whether geolocating an upload/login IP in a CSAM report is a "search" is not squarely decided in this context; *Carpenter v. United States*, 138 S. Ct. 2206 (2018) (https://supreme.justia.com/cases/federal/us/585/16-402/) found a reasonable-expectation-of-privacy in long-term historical cell-site location, but a single upload IP the provider already transmitted is closer to non-content metadata. The schema treats F4 as low-risk **[inference]**, and the design must stay agnostic to a future ruling that narrows IP-based geolocation.

**4. Statutory amendment recency creates citation drift.** The § 2258A(h) preservation period was raised from 90 days to **1 year** by the 2024 REPORT Act; older case law and commentary cite the 90-day figure (C6). The schema's preservation-clock assumptions (relevant to deferring low-priority F3/F6 reports) must track the current 1-year period, and any future amendment shifts the window again. Citations to § 2258A here are to the current Cornell LII text (https://www.law.cornell.edu/uscode/text/18/2258A), retrieved 2026-06-24.

**Where the schema must stay agnostic (synthesis):** (a) F3 must never *require* opening a file — so it is lawful across the circuit split; (b) NCMEC-side enrichment is treated as potential government action, not assumed private; (c) viewing-dependent values (age in F7, content-derived imminence in F1/F2) default to the *textual provider field*, with the open-the-file path reserved for warrant-backed handling; (d) cross-agency routing (F4) and sender feedback (F5) stay within § 2258A(g) permitted disclosures and never return visual depictions to providers. These four rules let the same schema be deployed in the 5th, 6th, 9th, and 10th Circuits without its priority scores depending on a search step that is lawful in one and suppressible in another.
